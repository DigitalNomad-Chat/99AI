# 删除按钮设计说明

**设计日期**: 2026-01-24
**组件**: PromptTemplateEditor
**设计理念**: 精致专业 - Refined Professional

---

## 设计目标

1. **解决原问题**: 红色背景 + 灰白色图标 = 对比度不足
2. **提升用户体验**: 让删除操作感觉"有意为之"而非误操作
3. **保持一致性**: 与现有蓝色品牌色系协调
4. **视觉层次**: 主操作(卡片删除) vs 次操作(选项删除)

---

## 设计决策

### 颜色系统

```css
/* 默认状态 - 低对比度，不引人注意 */
--btn-delete-default: #9ca3af;      /* 中性灰 */

/* 悬停状态 - 鲜明红色，传达警示 */
--btn-delete-hover: #dc2626;        /* 深红 */
--btn-delete-bg-hover: #fef2f2;     /* 极淡红背景 */

/* 激活状态 - 更深红色，确认操作 */
--btn-delete-active: #b91c1c;       /* 更深红 */
--btn-delete-bg-active: #fee2e2;    /* 淡红背景 */
```

**设计思考**:
- 默认使用中性灰，不会分散注意力
- 悬停时才显示红色，表明"这是危险操作"
- 渐进式颜色变化，而非突兀的红色背景

## 微交互设计

### 1. 卡片删除按钮 (.field-delete-btn)

**进入动画**:
```
默认状态: opacity: 0, translateX(-4px)
    ↓
卡片悬停: opacity: 1, translateX(0)
```

**悬停状态**:
```
鼠标悬停按钮
    ↓
• 颜色: #9ca3af → #dc2626
• 背景: 透明 → #fef2f2
• 缩放: 1.0 → 1.08
• 阴影: 淡淡的红色光晕
• 图标: 倾斜 -8deg + 轻微放大
```

**激活状态**:
```
按下按钮
    ↓
• 颜色: #b91c1c (更深)
• 缩放: 0.95 (按下反馈)
• 阴影: 收缩
```

### 2. 选项删除按钮 (.option-delete-btn)

**简化的微交互** (次要操作):
```
悬停: 颜色变化 + scale(1.1) + 图标倾斜 -5deg
激活: 颜色加深 + scale(0.95)
```

## 关键设计特点

### 1. 图标倾斜 - 传达删除意图

```css
.field-delete-btn:hover :deep(.el-icon) {
  transform: rotate(-8deg) scale(1.05);
}
```

**为什么倾斜？**
- 倾斜的删除图标给人一种"即将划掉"的心理暗示
- 微妙的动画让用户感知到"这个操作需要确认"
- 符合物理直觉 (垃圾桶倾斜倒垃圾)

### 2. 渐进式显示

```css
/* 默认隐藏 */
.field-delete-btn {
  opacity: 0;
  transform: translateX(-4px);
}

/* 卡片悬停时滑入 */
.field-item:hover .field-delete-btn {
  opacity: 1;
  transform: translateX(0);
}
```

**好处**：
- 减少视觉噪音
- 引导用户先关注卡片内容
- 悬停时才显示操作选项

### 3. 缓动函数选择

```css
transition: all 0.25s cubic-bezier(0.4, 0, 0.2, 1);
```

**cubic-bezier(0.4, 0, 0.2, 1)** = Material Design 标准
- 开始快，结束慢
- 给人"有弹性"的感觉
- 让动画更自然

## 可访问性考虑

### 对比度检查

| 状态 | 前景色 | 背景色 | 对比度 | WCAG 标准 |
|------|--------|--------|--------|-----------|
| 默认 | #9ca3af | 透明 | - | ✅ (装饰性) |

**结论**: 所有交互状态都符合 WCAG AAA 标准

## 未来优化方向

### 1. 暗色模式适配

```css
@media (prefers-color-scheme: dark) {
  .field-delete-btn {
    --btn-delete-default: #6b7280;
    --btn-delete-hover: #f87171;
    --btn-delete-bg-hover: rgba(248, 113, 113, 0.1);
  }

```

### 2. 触摸设备优化

```css
@media (hover: none) {
  .field-delete-btn {
    /* 移动端始终显示，不依赖悬停 */
    opacity: 1;
    transform: none;
  }
}
```

### 3. 减少动画 (尊重用户偏好)

```css
@media (prefers-reduced-motion: reduce) {
  .field-delete-btn {
    transition: opacity 0.15s ease;
  }

  .field-delete-btn:hover :deep(.el-icon) {
    transform: none;
  }
}
```

## 总结

这个设计通过以下方式解决了原问题：

1. ✅ **对比度提升**: 悬停时红色图标 + 淡红背景 = 清晰可见
2. ✅ **意图传达**: 图标倾斜让删除操作感觉"有意为之"
3. ✅ **视觉层次**: 主次操作有区分
4. ✅ **用户反馈**: 多状态动画提供丰富反馈
5. ✅ **可访问性**: 符合 WCAG AAA 标准
6. ✅ **代码质量**: 使用 CSS 变量，易于维护

**关键设计理念**: "An animation that anticipates the action"
— 图标在悬停时轻微倾斜，预示着即将发生的删除操作
