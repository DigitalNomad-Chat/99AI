## 1. TypeORM Synchronize 基本原理

### 1.1 什么是 Synchronize

`synchronize` 是 TypeORM 提供的自动数据库架构同步功能。当启用时，TypeORM 会：

- **自动创建表**: 根据 Entity 定义创建不存在的表
- **自动创建列**: 根据 `@Column` 装饰器添加缺失的列
- **自动更新列类型**: 修改列的数据类型以匹配 Entity 定义
- **自动创建索引**: 根据 `@Index` 装饰器创建索引
- **自动创建外键**: 根据 `@ManyToOne`、`@OneToMany` 等关系创建外键约束

### 1.2 Synchronize 的能力边界

**能做什么:**
- ✅ 创建新表
- ✅ 添加新列
- ✅ 更新列的数据类型
- ✅ 创建索引
- ✅ 创建外键约束

**不能做什么:**
- ❌ 删除表
- ❌ 删除列
- ❌ 删除数据
- ❌ 重命名列（需要先删除再添加）
- ❌ 数据迁移或转换

### 1.3 Synchronize 的风险

| 风险类型 | 描述 | 影响 |
|---------|------|-----|
| **数据丢失** | 修改列类型可能导致数据截断或丢失 | 高 |
| **性能问题** | 在生产环境对大表执行 ALTER TABLE 可能锁表 | 高 |
| **意外变更** | Entity 定义错误可能被同步到数据库 | 中 |
| **不可逆操作** | 某些同步操作无法轻易回滚 | 高 |

## 2. 智能同步策略

### 2.1 策略设计目标

项目采用**智能同步策略**，旨在解决以下矛盾：

- **开发便利性**: 希望自动同步减少手动操作
- **生产安全性**: 需要保护历史数据不被意外修改
- **部署灵活性**: 支持全新部署和升级部署两种场景

### 2.2 核心逻辑

```typescript
// 伪代码展示核心逻辑
async function initDatabase() {
  // 步骤1: 检查数据库状态
  const tableCount = await getTableCount();

  // 步骤2: 决定是否启用同步
  let useSynchronize = false;
  if (tableCount === 0) {
    // 空数据库：启用同步
    useSynchronize = true;
  } else {
    // 已有数据：禁用同步
    useSynchronize = false;
  }

  // 步骤3: 执行相应的初始化
  if (useSynchronize) {
    await initializeWithSynchronize();
  } else {
    await initializeWithoutSynchronize();
  }
}
```

### 2.3 实现代码位置

**文件**: `service/src/modules/database/initDatabase.ts`

**关键代码段**:

```typescript
// 检查数据库是否为空（是否有表存在）
let useSynchronize = false;
const checkConn = await mysql.createConnection({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASS,
  port: parseInt(process.env.DB_PORT, 10),
  database: process.env.DB_DATABASE,
});

try {
  const [tables] = (await checkConn.execute(
    `SELECT COUNT(*) as count FROM information_schema.tables
     WHERE table_schema = ?`,
    [process.env.DB_DATABASE],
  )) as mysql.RowDataPacket[];

  const tableCount = tables[0]?.count || 0;
  Logger.log(`当前数据库表数量: ${tableCount}`, 'Database');

  // 如果数据库为空（没有表），启用同步
  if (tableCount === 0) {
    Logger.warn('检测到空数据库，启用 TypeORM 同步以创建表结构', 'Database');
    useSynchronize = true;
  } else {
    Logger.log('数据库已存在表，禁用 TypeORM 同步以保护历史数据', 'Database');
    useSynchronize = false;
  }
} catch (error) {
  Logger.warn(`检查数据库状态失败: ${error.message}，默认禁用同步`, 'Database');
  useSynchronize = false;
} finally {
  await checkConn.end();
}

// --- 根据数据库状态选择同步策略 ---
if (useSynchronize) {
  // 全新数据库：启用同步创建所有表和字段
  Logger.warn('正在创建数据库表结构（同步模式）...', 'Database');
  const syncOptions: DataSourceOptions = {
    ...dataSourceOptions,
    synchronize: true,
  };
  const syncDataSource = new DataSource(syncOptions);
  await syncDataSource.initialize();
  Logger.log('数据库结构同步完成', 'Database');

  if (syncDataSource.isInitialized) {
    await syncDataSource.destroy();
  }

  Logger.warn('同步已完成，后续启动将禁用同步保护数据', 'Database');
} else {
  // 已有数据：禁用同步保护历史数据
  const dataSource = new DataSource(dataSourceOptions);
  await dataSource.initialize();
  Logger.log('已连接到数据库（同步已禁用）', 'Database');

  if (dataSource.isInitialized) {
    await dataSource.destroy();
  }
}
```

## 3. 部署场景说明

### 3.1 场景一：全新部署

**触发条件**: 数据库为空（表数量 = 0）

**执行流程**:

```
启动服务
    ↓
检查数据库状态
    ↓
发现表数量 = 0
    ↓
启用 synchronize = true（临时）
    ↓
TypeORM 同步创建所有表和字段
    ↓
同步完成，立即销毁 DataSource
    ↓
服务启动成功
```

**关键机制 - 自动关闭**:

```
┌─────────────────────────────────────────────────────────────┐
│                  一次性同步机制                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  const syncOptions = {                                      │
│    synchronize: true  ← 仅存在于局部变量                    │
│  }                                                         │
│                                                             │
│  const syncDataSource = new DataSource(syncOptions);        │
│  await syncDataSource.initialize();  ← 执行同步             │
│                                                             │
│  await syncDataSource.destroy();  ← 立即销毁！              │
│                                                             │
│  ✅ 没有全局状态持久化                                       │
│  ✅ 没有写入配置文件                                         │
│  ✅ 下次启动重新检测数据库状态                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**日志示例**:

```
[Database] 开始数据库初始化流程
[Database] 执行数据库迁移操作
[Database] 数据迁移操作完成
[Database] 当前数据库表数量: 0
[Database] 检测到空数据库，启用 TypeORM 同步以创建表结构
[Database] 正在创建数据库表结构（同步模式）...
[Database] 数据库结构同步完成
[Database] 同步已完成，后续启动将禁用同步保护数据
[Database] 数据库初始化成功完成
```

**结果**:
- ✅ 所有 Entity 对应的表都被创建
- ✅ 所有列都根据 Entity 定义创建
- ✅ 工作流相关字段（appType、workflowApiUrl 等）自动创建
- ✅ 索引和外键约束自动创建
- ✅ **同步完成后自动禁用，无需手动操作**

### 3.2 场景二：升级部署

**触发条件**: 数据库已有表（表数量 > 0）

**执行流程**:

```
启动服务
    ↓
检查数据库状态
    ↓
发现表数量 > 0
    ↓
禁用 synchronize = false
    ↓
仅连接数据库，不同步结构
    ↓
服务启动成功
```

**日志示例**:

```
[Database] 开始数据库初始化流程
[Database] 执行数据库迁移操作
[Database] 数据迁移操作完成
[Database] 当前数据库表数量: 20
[Database] 数据库已存在表，禁用 TypeORM 同步以保护历史数据
[Database] 已连接到数据库（同步已禁用）
[Database] 数据库初始化成功完成
```

**结果**:
- ✅ 数据库结构保持不变
- ✅ 历史数据完全安全
- ✅ 只执行列类型升级迁移（如有需要）
- ⚠️ 不会自动添加新字段（如需添加新字段，需手动执行 SQL）

## 4. 安全保证与限制

### 4.1 安全保证

| 保证机制 | 实现方式 | 保护效果 |
|---------|---------|---------|
| **空库检测** | 查询 `information_schema.tables` | 确保只在空数据库启用同步 |
| **默认禁用** | `synchronize: false` | 出错时默认保护数据 |
| **一次性同步** | 同步后立即禁用 | 防止每次启动都同步 |
| **非破坏性** | synchronize 不删除数据 | 即使启用也不会丢失数据 |

### 4.2 限制说明

1. **列类型迁移**: synchronize 可能修改列类型，可能导致数据截断
2. **外键约束**: 自动创建的外键可能影响现有数据
3. **性能影响**: 大表同步时可能锁表，影响服务可用性

### 4.3 最佳实践

**当前智能同步策略**:

项目采用**智能同步策略**，实现了自动化和安全的平衡：

| 部署场景 | 数据库状态 | synchronize 行为 | 是否安全 |
|---------|-----------|-----------------|---------|
| **首次全新部署** | 空库（表数 = 0） | 自动启用 → 创建表 → 自动销毁 | ✅ 安全 |
| **已有数据部署** | 有表（表数 > 0） | 自动禁用 → 仅连接 | ✅ 安全 |
| **服务重启/更新** | 有表（表数 > 0） | 自动禁用 → 仅连接 | ✅ 安全 |

✅ **推荐做法**:
- **信任智能同步策略**: 首次部署会自动创建表结构，无需手动干预
- **已有数据库添加字段**: 手动执行 ALTER TABLE SQL 语句
- **备份重要数据**: 在任何数据库操作前先备份
- **查看日志确认**: 通过日志确认同步状态和结果

❌ **禁止做法**:
- **手动修改代码强制启用同步**: 不要将 `synchronize: true` 写死在配置中
- **在有数据的数据库上测试同步**: 测试同步应使用空数据库
- **跳过备份直接操作**: 任何数据库变更前都应该备份

### 4.4 核心特点

```
┌─────────────────────────────────────────────────────────────┐
│                    智能同步策略特点                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ✅ 全自动化：首次部署无需任何手动操作                        │
│  ✅ 自动关闭：同步完成后自动禁用，无需人工干预                 │
│  ✅ 每次独立：每次启动都重新检测，不依赖历史状态                │
│  ✅ 安全优先：有数据时自动禁用，保护历史数据                   │
│  ✅ 零配置：无需修改配置文件，开箱即用                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 故障排除指南

### 5.1 问题: 数据库表创建失败

**症状**:
```
[Database] 检测到空数据库，启用 TypeORM 同步以创建表结构
[Database] 正在创建数据库表结构（同步模式）...
QueryFailedError: ...
```

**可能原因**:
1. 数据库连接参数错误
2. 数据库用户权限不足
3. 数据库不存在

**解决步骤**:

```bash
# 1. 检查数据库连接
mysql -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p<DB_PASS> <DB_DATABASE>

# 2. 验证用户权限
SHOW GRANTS FOR CURRENT_USER();

# 确保拥有以下权限:
# - CREATE (创建表)
# - ALTER (修改表结构)
# - INDEX (创建索引)
# - REFERENCES (创建外键)
```

### 5.2 问题: 列类型迁移失败

**症状**:
```
[Database] 迁移app表catId列时跳过: ...
```

**可能原因**:
1. 列不存在
2. 外键约束阻止修改
3. 索引冲突

**解决步骤**:

```sql
-- 1. 检查列是否存在
SELECT COLUMN_NAME, DATA_TYPE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'your_database' AND TABLE_NAME = 'app';

-- 2. 检查外键约束
SELECT CONSTRAINT_NAME
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = 'your_database'
  AND TABLE_NAME = 'app'
  AND COLUMN_NAME = 'catId';

-- 3. 检查索引
SELECT INDEX_NAME
FROM INFORMATION_SCHEMA.STATISTICS
WHERE TABLE_SCHEMA = 'your_database'
  AND TABLE_NAME = 'app'
  AND COLUMN_NAME = 'catId';
```

### 5.3 问题: 同步后字段缺失

**症状**: Entity 定义了字段，但数据库中没有

**原因**: 数据库已有数据，synchronize 被禁用

**解决方案**:

**手动添加字段**:

```sql
-- 示例：添加新字段
ALTER TABLE `app`
ADD COLUMN `newField` VARCHAR(255) NULL
COMMENT '字段说明';
```

## 6. 常见问题 FAQ

### Q1: 首次部署后 synchronize 如何自动关闭？

**A**: 无需手动关闭！智能同步策略实现了自动关闭机制：

**工作原理**:

1. **临时局部变量**: `synchronize: true` 只存在于局部变量 `syncOptions`
2. **立即销毁**: 同步完成后立即调用 `destroy()` 销毁 DataSource
3. **每次重新检测**: 下次启动时重新检测数据库状态
4. **自动决策**: 有数据时自动禁用同步

**代码示意**:

```typescript
// 仅在检测到空数据库时执行
const syncOptions: DataSourceOptions = {
  ...dataSourceOptions,
  synchronize: true,  // ← 只在这个局部变量中
};

const syncDataSource = new DataSource(syncOptions);
await syncDataSource.initialize();  // ← 执行同步

if (syncDataSource.isInitialized) {
  await syncDataSource.destroy();  // ← 立即销毁！
}
// syncOptions 在此作用域结束后被垃圾回收
```

**三次启动对比**:

| 启动次数 | 数据库表数量 | synchronize | 行为 |
|---------|------------|------------|-----|
| 第1次 | 0 | true (临时) | 创建表 → 自动销毁 DataSource |
| 第2次 | 20 | false | 仅连接数据库 |
| 第N次 | 20 | false | 仅连接数据库 |

### Q2: 为什么不直接启用 synchronize？

**A**: 因为 synchronize 在生产环境有风险：
- 可能修改列类型导致数据丢失
- 大表同步时锁表影响服务
- Entity 定义错误会被同步到数据库

**智能同步策略解决了这个问题**：
- 首次部署（空库）：自动启用，安全创建表结构
- 有数据部署：自动禁用，保护历史数据
- 全自动化，无需人工干预

### Q3: 如何在已有数据库添加新字段？

**A**: 手动执行 SQL 语句：

```sql
ALTER TABLE `app` ADD COLUMN `newField` VARCHAR(255) NULL COMMENT '字段说明';
```

### Q4: 开发环境可以启用 synchronize 吗？

**A**: 不建议！智能同步策略已经处理了所有场景：

- **开发环境首次启动**: 自动启用同步创建表
- **开发环境后续启动**: 自动禁用同步保护数据
- **无需修改代码**: 保持智能策略即可

如果需要强制同步（不推荐）：

```typescript
// ⚠️ 谨慎使用：可能导致数据丢失
const dataSourceOptions: DataSourceOptions = {
  // ...
  synchronize: true,  // ⚠️ 仅在测试环境使用
};
```

### Q5: 如何验证同步是否成功？

**A**: 检查日志和数据库：

```bash
# 1. 查看日志
# 应该看到: "数据库结构同步完成"

# 2. 验证表结构
DESCRIBE app;
SHOW FULL COLUMNS FROM app;

# 3. 验证特定字段
SELECT COLUMN_NAME, COLUMN_TYPE, COLUMN_COMMENT
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'app'
  AND COLUMN_NAME IN ('appType', 'workflowApiUrl');
```

### Q6: 列类型迁移 (migrateColumnType) 是做什么的？

**A**: 用于升级早期数据库的列类型：

| 表名 | 列名 | 原类型 | 目标类型 |
|------|------|--------|---------|
| config | configVal | VARCHAR | TEXT |
| app | coverImg | VARCHAR | TEXT |
| app | catId | INT | TEXT |
| chatlog | content | TEXT | MEDIUMTEXT |
| chatlog | fileVectorResult | TEXT | MEDIUMTEXT |

这些迁移是**一次性**的，如果列已经是目标类型，不会重复执行。
