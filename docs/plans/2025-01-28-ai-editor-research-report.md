# 主流AI Chat项目文章编辑器功能研究报告

**研究者**: Claude Code
**目的**: 研究成熟开源AI Chat项目的文章编辑器实现，避免重复造轮子

## 二、研究发现

### 2.1 LobeHub (LobeChat)

**✅ 已实现的相关功能:**

1. **Artifacts Support** (类似Claude Artifacts)
   - 可以生成和显示动态SVG图形
   - 可以构建和渲染交互式HTML页面
   - 可以生成多种格式的专业文档
   - **特点**: 实时创建和可视化，但**不是独立的侧边栏编辑器**

2. **Markdown 渲染支持**
   - 完整的Markdown渲染支持
   - 代码高亮 (highlight.js)
   - LaTeX公式
   - Mermaid流程图
   - **实现方式**: 使用专门的Markdown渲染组件

3. **持久化助手侧边栏** (v1.26.0)
   - 快速切换不同的助手
   - **用途**: 用于切换AI助手，**不是用于文档编辑**

4. **Branching Conversations**
   - 从任何消息创建新的对话分支
   - 保留原始上下文
   - **特点**: 对话树形结构，但**不是文档编辑**

**❌ 未发现的功能:**
- ❌ 独立的文档/文章编辑器
- ❌ 侧边栏文档预览和编辑
- ❌ AI辅助改写文章内容的专门界面

**GitHub**: https://github.com/lobehub/lobe-chat

---

### 2.2 Open WebUI

**✅ 已实现的相关功能:**

1. **TipTap 富文本编辑器**
   - 使用TipTap作为聊天输入框的富文本编辑器
   - 有格式化工具栏
   - 支持Markdown语法
   - **特点**: 专注于**输入框**的格式化，不是独立的文档编辑器

2. **Markdown 渲染**
   - 完整的Markdown渲染支持
   - 代码块语法高亮
   - 改进的换行处理

3. **文件管理/知识库**
   - 可以上传文件
   - 创建知识库
   - 在对话中引用文件
   - **特点**: 文档管理，但**不是实时编辑**

4. **工作区功能** (Fileshed)
   - 持久化工作区
   - 跨对话存储和组织文件
   - 协作和共享文件

**❌ 未发现的功能:**
- ❌ 独立的侧边栏文章编辑器
- ❌ 类似豆包的文档卡片弹出功能
- ❌ 在侧边栏中预览+编辑文档的一体化功能

**GitHub**: https://github.com/open-webui/open-webui

---

### 2.3 Cherry Studio & Chatbox

## 三、核心发现总结

### 3.1 重要发现

🔍 **关键发现**: **主流开源AI Chat项目都没有实现类似豆包/千问的独立文章编辑器功能！**

| 功能 | LobeHub | Open WebUI | 豆包/千问 |
|------|---------|------------|-----------|
| Markdown渲染 | ✅ | ✅ | ✅ |
| 富文本输入框 | ✅ | ✅ | ✅ |
| Artifacts/代码生成 | ✅ | ❌ | ❌ |
| 独立文档编辑器 | ❌ | ❌ | ✅ |
| 侧边栏文档预览 | ❌ | ❌ | ✅ |
| AI辅助改写 | ❌ | ❌ | ✅ |

### 3.2 为什么开源项目没有实现？

**推测原因:**

1. **复杂度高**
   - 需要独立的文档状态管理
   - 需要实时同步和冲突处理
   - 需要版本控制

2. **使用场景不同**
   - 开源项目专注于**对话**场景
   - 豆包/千问定位于**写作助手**场景

3. **技术架构差异**
   - 开源项目: 对话流式处理
   - 商业产品: 文档+对话双模式

## 四、对我们的启示

### 4.1 我们的选择

**方案评估:**

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **完全参考开源方案** | 技术成熟、社区支持 | **无法实现您想要的效果** | ❌ 不推荐 |
| **参考豆包/千问实现** | 符合预期、功能完整 | 需要从0开发、工作量大 | ⚠️ 可行 |
| **混合方案** | 平衡功能和开发成本 | 需要自行设计架构 | ✅ **推荐** |

### 4.2 建议的技术实现

#### 核心功能需求

```
┌─────────────────────────────────────────────────────┐
│  用户需求分析                                         │
├─────────────────────────────────────────────────────┤
│  1. 生成文章后弹出独立预览卡片                        │
│  2. 右侧滑出编辑器侧边栏                              │
│  3. 预览模式: 完整Markdown渲染                        │
│  4. 编辑模式: TipTap富文本编辑                        │
│  5. AI辅助: 改写、续写、润色、翻译                     │
│  6. 流式生成: 打字机效果显示                          │
└─────────────────────────────────────────────────────┘
```

#### 推荐架构

```
前端架构:
┌──────────────────────────────────────────────────┐
│  Main Chat Interface                             │
│  ├─ Message List                                 │
│  └─ Writing Button → 触发文章生成                 │
└──────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────┐
│  Article Drawer (右侧滑出)                        │
│  ├─ Header: 预览/编辑切换 + 关闭                   │
│  ├─ Content Area:                                │
│  │   ├─ Preview Mode: v-html Markdown渲染         │
│  │   └─ Edit Mode: TipTap富文本编辑器             │
│  └─ Footer: AI辅助操作按钮                        │
└──────────────────────────────────────────────────┘

状态管理:
- articleStore: 管理文章列表和当前文章
- 支持多个文章并存
- 版本历史记录
```

#### 技术选型

| 模块 | 推荐技术 | 理由 |
|------|----------|------|
| **Markdown渲染** | MarkdownIt + highlight.js | 项目已在使用，成熟稳定 |
| **富文本编辑器** | TipTap v2.27.2 | 已集成，MIT协议，功能强大 |
| **状态管理** | Pinia | 项目已使用 |
| **侧边栏组件** | 自定义Drawer | 更灵活的定制控制 |
| **流式显示** | 打字机效果 | 已实现，效果良好 |

## 六、结论

### 6.1 核心结论

1. **开源项目没有现成方案**: 主流开源AI Chat项目都没有实现类似豆包的独立文章编辑器功能
2. **我们的方向正确**: 既然没有参考，我们的实现本身就是创新
3. **当前实现可用**: 预览/编辑模式切换方案符合核心需求

### 6.2 下一步建议

**优先级排序:**

🔴 **P0 - 立即修复**
1. 修复后端文章内容解析问题
2. 确保打字机效果正常工作

🟡 **P1 - 核心功能**
1. 完善预览/编辑模式切换
2. 实现AI辅助改写功能

🟢 **P2 - 增强功能**
1. 多文章管理
2. 导出功能

### 6.3 最终建议

**继续当前方案，但需要:**
1. 不要过度追求"参考成熟项目"
2. 专注于用户体验和功能完整性
3. 逐步迭代优化

**当前方案的优势:**
- ✅ 已有基础架构
- ✅ 技术栈成熟
- ✅ 符合核心需求

**建议调整:**
- 保持简单，先让功能可用
- 逐步完善细节
- 基于用户反馈迭代
