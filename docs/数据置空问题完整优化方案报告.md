## 二、根本原因分析

### 2.1 核心问题：**数据写入路径没有保护字段**

#### 问题1: models 表 - setModel 方法

**文件**: `service/src/modules/models/models.service.ts:191-289`

**当前状态**: ✅ **已添加字段保护**

```typescript
// 已有的保护逻辑
updateData.modelName = updateData.modelName || curModel.modelName || '默认模型';
updateData.model = updateData.model || curModel.model || 'gpt-3.5-turbo';
```

**结论**: models 表的保护已经到位，不应再出现置空问题。

---

#### 问题2: chatlog 表 - saveChatLog 方法 ⚠️

**文件**: `service/src/modules/chatLog/chatLog.service.ts:37-40`

**当前状态**: ❌ **没有字段保护**

```typescript
async saveChatLog(logInfo): Promise<any> {
  const savedLog = await this.chatLogEntity.save(logInfo);  // 直接保存，没有任何保护
  return savedLog;
}
```

**问题分析**：

1. **TypeORM 的 `.save()` 方法行为**：
   ```typescript
   // 如果 logInfo 中某个字段是 undefined：
   this.chatLogEntity.save({
     role: undefined,  // ← 会保存为 NULL
     model: undefined, // ← 会保存为 NULL
     modelName: undefined, // ← 会保存为 NULL
   })
   ```

2. **调用方的问题**（`chat.service.ts:406-441`）：
   ```typescript
   // 用户消息
   const userSaveLog = await this.chatLogService.saveChatLog({
     model: useModel,
     modelName: '我',  // ← 硬编码为 '我'，可能不是用户期望的
     role: 'user',
     // ... 其他字段
   });

   // 助手消息
   const assistantSaveLog = await this.chatLogService.saveChatLog({
     model: useModel,
     modelName: useModeName,  // ← 来自请求参数，可能是 undefined
     role: 'assistant',
     // ... 其他字段
   });
   ```

3. **`modelName` 变量来源**（`chat.service.ts:61,392`）：
   ```typescript
   const { modelName } = body;  // 从请求体解构
   const useModeName = modelName;  // 直接赋值
   ```
   - 如果前端没有传 `modelName`，它会是 `undefined`
   - `undefined` 保存到数据库会变成 `NULL`

---

#### 问题3: 前端草稿恢复功能 ⚠️

**文件**: `admin/src/views/app/application.vue`

**新增的草稿功能可能引入的问题**：

```typescript
// 草稿恢复逻辑
const restoreDraft = () => {
  Object.assign(formPackage, draftData.value.formPackage);
  specialModelType.value = draftData.value.specialModelType;
  // ...
};
```

**潜在问题**：
- 如果草稿数据是在 HMR 触发前保存的
- HMR 重置了 `formPackage` 的某些字段
- 恢复草稿时，草稿数据本身可能就不完整

**结论**: 草稿功能主要影响前端，**不应该直接影响后端数据库**。

---

### 2.2 问题传播路径

```
用户发起对话（前端）
    ↓
chat.service.ts: 方法接收请求
    ↓
chat.service.ts:392 → const useModeName = modelName
    ↓
chat.service.ts:431 → modelName: useModeName
    ↓
chatLog.service.ts:37 → saveChatLog({ modelName: useModeName })
    ↓
chatLog.service.ts:38 → chatLogEntity.save(logInfo)
    ↓
数据库: UPDATE/INSERT chatlog SET modelName = NULL
```

**关键点**: 如果 `modelName` 是 `undefined`，数据库会保存为 `NULL`。

## 三、完整解决方案

### 3.1 短期方案（立即执行）

#### 方案A: 修复 chatlog.saveChatLog 方法

**文件**: `service/src/modules/chatLog/chatLog.service.ts`

**修改内容**：

```typescript
async saveChatLog(logInfo): Promise<any> {
  // 确保 model 和 modelName 有默认值
  const saveData = {
    ...logInfo,
    // 保护关键字段，避免 undefined 导致 NULL
    model: logInfo.model || 'gpt-3.5-turbo',
    modelName: logInfo.modelName || logInfo.model || 'AI',
    role: logInfo.role || 'assistant',
  };

  const savedLog = await this.chatLogEntity.save(saveData);
  return savedLog;
}
```

**优点**:
- ✅ 简单直接
- ✅ 在数据写入源头保护字段
- ✅ 不影响现有调用逻辑

**缺点**:
- ⚠️ 硬编码的默认值可能不是所有场景都适用
- ⚠️ 如果后续有其他调用场景，可能需要调整

---

#### 方案B: 在调用方确保数据完整

**文件**: `service/src/modules/chat/chat.service.ts`

**修改内容**：

```typescript
// 第392行：确保 useModeName 有值
const useModeName = modelName || model || 'AI';

// 第431行：确保 assistantSaveLog 的 modelName 有值
const assistantSaveLog = await this.chatLogService.saveChatLog({
  // ...
  model: useModel,
  modelName: useModeName || useModel || 'AI',  // 双重保险
  role: 'assistant',
  // ...
});
```

**优点**:
- ✅ 在数据源头确保完整性
- ✅ 不依赖 saveChatLog 的保护逻辑
- ✅ 更精确的默认值选择

**缺点**:
- ⚠️ 需要修改多个调用点
- ⚠️ 未来新增调用点时容易遗漏

---

### 3.2 推荐方案：组合保护（A + B）

**同时实施方案A和方案B**，形成双重保护：

1. **chat.service.ts**：在数据源头确保完整性（第一道防线）
2. **chatLog.service.ts**：在 saveChatLog 中兜底保护（第二道防线）

**好处**：
- ✅ 双重保险，确保万无一失
- ✅ 即使某处修改遗漏，另一处也能保护
- ✅ 未来代码变更更安全

#### 3. 数据库触发器（可选）

为 chatlog 表创建 BEFORE INSERT 触发器：

```sql
CREATE TRIGGER chatlog_before_insert
BEFORE INSERT ON chatlog
FOR EACH ROW
BEGIN
  -- 如果 model 为 NULL，设置默认值
  IF NEW.model IS NULL THEN
    SET NEW.model = 'gpt-3.5-turbo';
  END IF;

  -- 如果 modelName 为 NULL，使用 model 的值
  IF NEW.modelName IS NULL THEN
    SET NEW.modelName = COALESCE(NEW.model, 'AI');
  END IF;

  -- 如果 role 为 NULL，设置默认值
  IF NEW.role IS NULL THEN
    SET NEW.role = 'assistant';
  END IF;
END;
```

**优点**：
- ✅ 数据库层面的最终保护
- ✅ 即使应用代码有bug，也不会写入 NULL

**缺点**：
- ⚠️ 增加数据库维护复杂度
- ⚠️ 需要额外的数据库迁移脚本
