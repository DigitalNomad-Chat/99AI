## 三、TypeORM 同步机制分析

### 3.1 当前同步配置

**`database.module.ts:67`**:
```typescript
synchronize: false, // 禁用自动同步
```

**`initDatabase.ts:240-265`**:
```typescript
// 先禁用同步的连接
const dataSource = new DataSource(dataSourceOptions);
await dataSource.initialize();

// 然后启用同步的连接
const syncOptions: DataSourceOptions = {
  ...dataSourceOptions,
  synchronize: true,  // ✅ 启用同步
};
const syncDataSource = new DataSource(syncOptions);
await syncDataSource.initialize();
```

**工作机制**:
1. 服务启动时调用 `initDatabase()`
2. 执行列类型迁移（`runAllMigrations`）
3. 启用 `synchronize: true` 同步新表和字段
4. 完成后关闭连接

### 3.2 TypeORM Synchronize 行为

**`synchronize: true` 会**:
- ✅ 创建不存在的新表
- ✅ 添加不存在的新字段
- ✅ 更新字段类型（如果 Entity 定义与数据库不一致）

**`synchronize: true` 不会**:
- ❌ 删除数据库中存在但 Entity 中没有的字段
- ❌ 删除表
- ❌ 删除数据

### 5.1 用户报告的问题

2. **用户发送的提示词变成AI回复的内容**

### 5.2 可能的原因

#### 假设 1: 历史数据字段为空

**问题**: 如果 `chatlog` 表中的旧数据：
- `role` 字段为 `null`
- `content` 字段为 `null`

**后果**:
```typescript
// chatLog.service.ts:239
content: content || (role === 'assistant' ? answer : prompt)
// 如果 content = null 且 role = null:
// 结果 = null || (null === 'assistant' ? answer : prompt)
//      = null || (false ? answer : prompt)
//      = prompt
// 这看起来是正确的，但如果 role 字段有问题就会出错
```

#### 假设 2: TypeORM Synchronize 的副作用

**风险**: 虽然理论上 `synchronize: true` 只添加不删除，但：
- TypeORM 可能会尝试同步 Entity 定义到数据库
- 如果有外键关系，可能会影响关联数据

#### 假设 3: 数据库连接问题

**可能**:
- 数据库连接配置变更
- 字符集问题（`utf8mb4`）
- 时区问题（`+08:00`）

### 9.2 用户报告的问题需要独立调查

**重要更新（2026-01-24）**：经过系统性调试，已找到数据丢失的真正原因！

#### 🔍 根本原因分析

**问题定位**：前端 `admin/src/views/app/application.vue` 的 `handleUpdatePackage` 函数存在字段遗漏问题。

**数据流分析**：

1. **前端 `formPackage` 初始化缺失字段**
   ```javascript
   const formPackage = reactive({
     // ... 其他字段
     // ⚠️ 缺少 role 字段！
   });
   ```

2. **前端 `handleUpdatePackage` 解构缺失字段**
   ```javascript
   const { name, status, des, order, ... } = row;
   // ⚠️ 解构时没有包含 role 字段！
   ```

3. **前端提交时包含 undefined 值**
   ```javascript
   const params = { ...formPackage, ... };
   // params.role = undefined
   ```

4. **后端 `updateApp` 没有保护所有字段**
   ```javascript
   const updateData = { ...body };  // 包含 role: undefined
   // ⚠️ 没有 nullish coalescing 保护 role 字段
   await this.appEntity.update({ id }, updateData);
   // TypeORM 执行: UPDATE app SET role = NULL WHERE id = ?
   ```

#### ✅ 已修复

**前端修复** (`admin/src/views/app/application.vue`):
1. 在 `formPackage` 初始化中添加 `role: 'system'`
2. 在 `handleUpdatePackage` 解构中添加 `role`
3. 在 `Object.assign` 中添加 `role: role || 'system'`

**后端修复** (`service/src/modules/app/app.service.ts`):
在 `updateApp` 方法中添加了对所有字段的保护：
```typescript
// 角色和描述相关字段
updateData.role = updateData.role ?? (curAppData.role || 'system');
updateData.des = updateData.des ?? (curAppData.des || '');
updateData.preset = updateData.preset ?? (curAppData.preset || '');
updateData.demoData = updateData.demoData ?? (curAppData.demoData || '');

// GPTs 相关字段
updateData.gizmoID = updateData.gizmoID ?? (curAppData.gizmoID || '');

// Flowith 相关字段
updateData.flowithKey = updateData.flowithKey ?? (curAppData.flowithKey || '');

// 其他字段
updateData.appModel = updateData.appModel ?? (curAppData.appModel || '');
updateData.coverImg = updateData.coverImg ?? (curAppData.coverImg || '');
// ... 工作流相关字段也添加了保护
```

#### 📊 修复效果

| 字段 | 修复前 | 修复后 |
|------|--------|--------|
| `role` | 更新时被置为 NULL | 保持原值 |
| `des` | 更新时被置为 NULL | 保持原值 |
| `preset` | 更新时被置为 NULL | 保持原值 |
| `demoData` | 更新时被置为 NULL | 保持原值 |
| `gizmoID` | 更新时被置为 NULL | 保持原值 |
| `flowithKey` | 更新时被置为 NULL | 保持原值 |
| `coverImg` | 更新时被置为 NULL | 保持原值 |

#### ⚠️ 结论

用户报告的字段值丢失问题**确实与代码修改有关**，但不是因为数据库结构变化，而是因为：
1. 前端代码遗漏了部分字段的处理
2. 后端代码没有对字段进行保护性更新

这是一个**长期存在的 BUG**，在本次工作流功能开发过程中暴露了出来。

**建议**：
1. 检查数据库中受影响的数据，必要时进行恢复
2. 测试修复后的更新功能
