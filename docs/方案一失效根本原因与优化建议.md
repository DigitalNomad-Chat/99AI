## 一、方案一为什么完全失效？

### 1.1 问题发现

**用户报告**："在修改代码的过程中，数据字段又被重置了"

**测试场景**：
1. 用户编辑应用/模型，填写了完整数据
2. 修改代码触发 HMR
3. 数据字段被置空

**方案一的设计**：
```typescript
// 草稿自动保存
watch(formPackage, () => {
  if (visible.value) {
    saveDraft();  // 保存到 localStorage
  }
});

// 打开新建对话框时检测草稿
function openCreateDialog() {
  const draft = getDraft();
  if (draft) {
    showDraftRestoreDialog.value = true;  // 提示恢复
    return;
  }
  resetFormToDefault();
  visible.value = true;
}
```

**致命缺陷**：
- ✅ 新建时有草稿检测
- ❌ **编辑时没有草稿检测！**

### 1.2 编辑模式的数据流

**application.vue 的 handleUpdatePackage**（第323-400行）：

```typescript
function handleUpdatePackage(row: any) {
  // ❌ 没有检测草稿！

  const { modelName, model, ... } = row;

  // 用数据库数据覆盖 formPackage

    Object.assign(formPackage, {
      modelName,  // ← 如果数据库中是空字符串，这里就是空字符串！
```

**问题**：
1. **没有草稿检测**
2. **直接用数据库数据覆盖 formPackage**
3. **如果数据库中某些字段是空值，就会加载空值**

## 二、HMR 导致数据重置的完整时间线

### 时间线

```
T0: 用户开始编辑应用/模型
    ↓
    formPackage 被填充数据库中的数据（完整）
    ↓
T1: 用户修改了某些字段
    ↓
    草稿自动保存 → localStorage（有草稿了）✅
    ↓
T2: 用户继续编辑...
    ↓
    【修改代码 → HMR 触发】
    ↓
    前端代码重新加载
    ↓
    formPackage 恢复为初始值（空字符串）❌
    ↓
    草稿数据还在 localStorage 中 ✅
    ↓
T3: 用户再次点击"编辑"按钮
    ↓
    handleUpdatePackage(row) 被调用
    ↓
    ❌ 不检测草稿，直接从数据库加载数据
    ↓
    如果数据库中某些字段是空的 → formPackage 加载空值
    ↓
T4: 用户点击"确认变更"
    ↓
    空值被提交到后端 → 数据库被置空
```

## 三、为什么数据库中的数据也会被置空？

### 3.1 可能的原因

**假设1：编辑时就有空值**
- 用户打开编辑时，数据库中某些字段本来就是空的
- handleUpdatePackage 加载了空值
- 用户没有注意到，点击了"确认变更"
- 空值被提交

**假设2：某次提交时的代码问题**
- 之前的代码版本没有字段保护
- 提交时空值被保存到数据库
- 现在即使有保护，也只是保护"新"的空值

**假设3：TypeORM synchronize**
- 某些 Entity 修改导致 TypeORM 同步时重置了数据
- （但可能性较小，因为我们检查过 Entity 定义）

---

### 3.2 关键发现

**草稿自动保存的问题**：

| 场景 | 草稿检测 | 结果 |
|------|---------|------|
| 新建应用 | ✅ 有检测 | 能恢复草稿 |
| 编辑应用 | ❌ 无检测 | **不能恢复草稿** |
| 编辑模型 | ❌ 无检测 | **不能恢复草稿** |

**结论**：草稿自动保存只解决了"新建"场景，没有解决"编辑"场景！

## 四、优化建议

### 方案A：修复方案一 - 添加编辑模式草稿检测（推荐）

**实施**：在 `handleUpdatePackage` 中添加草稿检测

**文件**: `admin/src/views/app/application.vue`

**修改位置**: 第323行

**修改内容**：

```typescript
function handleUpdatePackage(row: any) {
  activeAppCatId.value = row.id;
  isUserApp.value = row.role === 'user';
  userAppStatus.value = row.status;

  // 【新增】检测编辑模式的草稿
  const draft = getDraft();
  if (draft && (draft.formPackage.name || draft.formPackage.des || draft.formPackage.catId.length > 0)) {
    // 检测草稿是否有更新的内容
    const hasNewerData =
      draft.formPackage.name !== row.name ||
      draft.formPackage.des !== row.des ||
      JSON.stringify(draft.formPackage.catId) !== JSON.stringify(row.catId);

    if (hasNewerData) {
      draftData.value = draft;
      showDraftRestoreDialog.value = true;
      return; // 等待用户选择
    }
  }

  // 原有的数据库加载逻辑...
}
```

**优点**：
- ✅ 解决编辑模式草稿问题
- ✅ 可以检测草稿是否有更新
- ✅ 用户体验好

**缺点**：
- ⚠️ 需要修改对话框逻辑，区分"新建"和"编辑"

## 七、总结

### 7.1 方案一为什么失效

1. **只覆盖新建场景**：草稿检测只在 `openCreateDialog` 中
2. **编辑没有检测**：`handleUpdatePackage` 不检测草稿，直接加载数据库数据
3. **数据库数据可能有问题**：如果之前某次提交保存了空值，会一直传递下去

### 7.2 真正的治本方案

**必须解决编辑模式的草稿检测**，这是核心问题！
