# AI写作编辑器功能调研与需求文档

## 用户原始需求

实现类似**豆包**、**千问**、**Gemini**那样的AI写作功能：

### 核心功能需求

1. **独立文章卡片**
   - 生成文章后，在聊天流中显示独立的文章卡片（而非普通消息）
   - 卡片展示文章标题、摘要、预览内容

2. **侧边栏文章预览**
   - 点击卡片后，从右侧弹出独立的侧边栏编辑器
   - 支持预览模式和编辑模式切换
   - 预览模式：完整的Markdown渲染（代码高亮、表格、公式等）
   - 编辑模式：富文本编辑器，支持手动修改

3. **AI辅助改写**
   - 在侧边栏编辑器中，选中文字后可调用AI改写
   - 支持的改写类型：
     - 续写（继续生成）
     - 改写（改变表述方式）
     - 扩写（扩展内容）
     - 缩写（精简内容）
     - 翻译（多语言互译）
     - 润色（优化语言表达）

4. **文章管理**
   - 文章保存为草稿
   - 导出为Markdown/HTML/PDF
   - 历史文章查看

### 四、关键发现

#### 🚨 核心结论

**这些主流开源项目都没有实现"豆包/千问/Gemini"式文章编辑功能！**

**原因分析：**

1. **产品定位差异**
   - 开源项目：定位是"AI对话工具"
   - 商业产品：定位是"AI写作助手"

2. **技术路径不同**
   - 开源项目：流式Markdown渲染
   - 商业产品：富文本编辑器 + 流式插入

3. **使用场景分离**
   - 开源项目的长文本写作通过外部工具（Notion、Obsidian）完成
   - 商业产品集成完整的写作工作流

### 五、商业产品的实现方式

#### Gemini Advanced / 豆包 / 千问的共同特点

```
┌─────────────────────────────────────────────────────────┐
│  对话区域                            [文章卡片]          │
│  ┌─────────────────────────────┐    ┌─────────────────┐│
│  │ 用户: 写一篇关于Spring的文章  │    │ ▼ 生成的文章    ││
│  ├─────────────────────────────┤    │ [点击展开]      ││
│  │ AI: 好的，我来帮你...        │    │                 ││
│  │ [文章卡片]                  │    └─────────────────┘│
│  └─────────────────────────────┘                       │
└─────────────────────────────────────────────────────────┘
                        ↓ 点击卡片
┌─────────────────────────────────────────────────────────┐
│  侧边栏文章编辑器                          [AI辅助菜单]  │
│  ┌─────────────────────────────────────┐  ┌───────────┐│
│  │ # 深入浅出Spring                     │  │ 续写      ││
│  │                                     │  │ 改写      ││
│  │ 在Java的世界里...                   │  │ 扩写      ││
│  │                                     │  │ 翻译      ││
│  │ ## 什么是Spring？                   │  │ 润色      ││
│  │                                     │  └───────────┘│
│  │ [选中文字→右键→AI改写]              │              ││
│  └─────────────────────────────────────┘              │
└─────────────────────────────────────────────────────────┘
```

#### 核心技术特征

1. **双层架构**：对话区 + 独立编辑区
2. **富文本编辑器**：Quill / ProseMirror / TipTap（非纯Markdown）
3. **流式内容插入**：边生成边插入，而非生成后整体显示
4. **上下文保持**：编辑器内容可作为后续对话的上下文
5. **AI工具栏**：集成多种AI辅助操作

### 六、对当前项目的建议

#### 🎯 核心问题

我们当前实现的状态：

| 功能 | 状态 | 说明 |
|------|------|------|
| 侧边栏抽屉 | ✅ 已实现 | SidebarDrawer组件 |
| TipTap编辑器 | ✅ 已实现 | 富文本编辑 |
| Markdown预览 | ✅ 已实现 | markdown-it + highlight.js |
| 预览/编辑切换 | ✅ 已实现 | 模式切换按钮 |
| **流式实时插入** | ❌ 缺失 | 目前是一次性打字机效果 |
| **独立文章卡片** | ❌ 缺失 | 聊天流中没有卡片组件 |
| **AI辅助改写** | ⚠️ 部分实现 | 后端接口已实现，前端未集成 |

#### 📋 改进方案对比

##### 方案A：最小改动（推荐）

**保持现有架构，优化体验：**

```
当前流程：
用户输入 → AI生成完整文章 → 打开抽屉 → 打字机效果显示

优化流程：
用户输入 → [文章卡片出现在聊天流] → 点击卡片 → 打开抽屉
```

**需要添加：**
1. 在聊天流中添加**文章卡片组件**
2. 卡片显示：标题、摘要（前100字）、预览
3. 点击卡片打开侧边栏编辑器
4. 修复当前的"空文章"bug

**工作量：** 1-2天

---

##### 方案B：完全对齐商业产品

**重大架构调整：**

```
1. 侧边栏编辑器实时流式插入（而非打字机效果）
2. 编辑器内集成AI改写工具栏/右键菜单
3. 编辑器内容作为对话上下文
4. 支持多个文章实例同时存在
5. 文章版本历史管理
```

**工作量评估：**
- 前端重构：3-5天
- 后端调整：2-3天
- 测试调试：2天
- **总计：约1-2周**

### 七、最终建议

#### 💡 我的建议

**不要过度对标商业产品！**

**理由：**

1. **用户群体不同**
   - 商业产品：面向普通用户，需要极简体验
   - 开源项目：面向开发者，功能优先级不同

2. **使用场景不同**
   - 大部分用户不需要复杂的"AI写作工作流"
   - 基础的生成+编辑+改写已能满足80%需求

3. **开发成本过高**
   - 完整实现需要1-2周
   - ROI（投资回报率）不高

#### ✅ 推荐的MVP功能

聚焦核心价值，实现以下功能即可：

1. ✅ **聊天流中的文章卡片**（显示标题+摘要）
2. ✅ **侧边栏编辑器**（已实现，需修复bug）
3. ✅ **基础AI改写**：选中文字 → 右键菜单 → 改写/扩写/翻译
4. ✅ **Markdown导出**

#### 🎯 具体行动步骤

**第一阶段（修复bug）**
1. 修复"空文章"问题
2. 确保打字机效果正常显示

**第二阶段（添加卡片）**
1. 创建ArticleCard组件
