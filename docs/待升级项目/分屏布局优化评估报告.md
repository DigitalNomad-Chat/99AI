# 分屏布局优化评估报告

> **项目：** 99AI HTML 预览功能侧边栏布局优化
> **创建日期：** 2026年1月23日
> **评估范围：** 从悬浮侧边栏到挤压式分屏布局的升级方案

---

## 一、问题分析

### 1.1 当前实现方式

```
┌─────────────────────────────────────────────┐
│                                             │
│          聊天界面 (100% 宽度)               │
│                                             │
│                              ┌──────────────┤
│                              │              │
│                              │  侧边栏       │ ← fixed 定位
│                              │  (z-index)   │   悬浮覆盖
│                              │              │
│                              └──────────────┘
└─────────────────────────────────────────────┘
```

**技术实现：**
- `position: fixed` + `right: 0`
- `z-index: 50` 悬浮在聊天界面之上
- 聊天界面保持 100% 宽度，被侧边栏遮挡
- 只能通过遮罩层（移动端）或关闭侧边栏查看被遮挡内容

### 1.2 主流平台实现方式

```
┌─────────────────────────────────┬─────────────┐
│                                 │             │
│     聊天界面 (压缩后)            │   侧边栏     │
│     约 50-60% 宽度              │   40-50%     │
│                                 │             │
│                                 │             │
└─────────────────────────────────┴─────────────┘
```

**参考产品：**
| 产品 | 布局方式 | 分屏比例 |
|------|----------|----------|
| **Claude** | 挤压式分屏 | 聊天 50% / 预览 50% |
| **Cursor** | 挤压式分屏 | 代码 60% / 预览 40% |
| **MarsCode (豆包)** | 挤压式分屏 | 聊天 55% / 预览 45% |
| **LobeChat** | 挤压式分屏 | 可拖拽调整 |

**核心优势：**
1. ✅ 同时看到对话内容和预览结果
2. ✅ 无遮挡，无遗漏信息
3. ✅ 符合用户对"分屏"的预期
4. ✅ 便于对比对话和代码

## 二、技术实现对比

### 2.1 当前方案：悬浮侧边栏

```css
/* HtmlSidebar.vue 当前实现 */
.html-sidebar-container {
  position: fixed;
  right: 0;
  width: 50%;
  z-index: 50;
  /* 聊天界面不受影响，保持 100% */
}
```

**优点：**
- ✅ 实现简单，不影响现有布局
- ✅ 动画效果流畅（transform: translateX）
- ✅ 移动端体验好（全屏覆盖）

**缺点：**
- ❌ 遮挡聊天内容
- ❌ 无法同时查看两边
- ❌ 与主流产品体验不一致

### 2.2 推荐方案：挤压式分屏

```css
/* 聊天容器动态宽度 */
.chat-container {
  width: calc(100% - var(--sidebar-width));
  transition: width 0.3s ease;
}

/* 侧边栏 */
.html-sidebar {
  position: fixed;
  right: 0;
  width: var(--sidebar-width);
}
```

**核心改动：**
1. 聊天容器宽度从 `100%` → `calc(100% - 50%)`
2. 侧边栏保持 `position: fixed`
3. 通过 CSS 变量或 Store 控制宽度

## 三、详细技术方案

### 3.1 方案 A：CSS Grid 布局（推荐）

**适用场景：** 大规模重构，追求最佳效果

```vue
<!-- App.vue -->
<template>
  <div class="app-layout" :class="{ 'with-sidebar': showSidebar }">
    <!-- 主内容区域 -->
    <div class="main-content">
      <router-view />
    </div>

    <!-- 侧边栏 -->
    <HtmlSidebar v-if="showSidebar" />
  </div>
</template>

<style scoped>
.app-layout {
  display: grid;
  grid-template-columns: 1fr;
  height: 100vh;
  transition: grid-template-columns 0.3s ease;
}

.app-layout.with-sidebar {
  grid-template-columns: 1fr 50%;
}

.main-content {
  min-width: 0; /* 防止内容溢出 */
}
</style>
```

**优点：**
- ✅ 布局稳定，无闪烁
- ✅ 性能最佳（GPU 加速）
- ✅ 响应式友好

**缺点：**
- ❌ 需要修改 App.vue 根布局
- ❌ 可能影响其他页面

---

### 3.2 方案 B：动态宽度类（推荐）

**适用场景：** 最小化改动，快速实现

```typescript
// store/modules/global/index.ts
state: (): GlobalState => ({
  // 新增：侧边栏状态
  sidebarVisible: false,
  sidebarWidth: 50, // 百分比
})

actions: {
  toggleSidebar(visible: boolean) {
    this.sidebarVisible = visible
    // 动态添加/移除类到 body
    if (visible) {
      document.body.classList.add('sidebar-open')
    } else {
      document.body.classList.remove('sidebar-open')
    }
  }
}
```

```css
/* 全局样式 */
.chat-wrapper {
  width: 100%;
  transition: width 0.3s ease;
}

body.sidebar-open .chat-wrapper {
  width: calc(100% - var(--sidebar-width, 50%));
}
```

**优点：**
- ✅ 改动最小
- ✅ 易于维护
- ✅ 兼容性好

**缺点：**
- ❌ 需要找到正确的聊天容器
- ❌ CSS 选择器可能较复杂

---

### 3.3 方案 C：CSS 变量控制

```css
:root {
  --sidebar-width: 0px;
}

body.has-sidebar {
  --sidebar-width: 50vw;
}

.chat-container {
  width: calc(100% - var(--sidebar-width));
}

.html-sidebar {
  width: var(--sidebar-width);
}
```

## 四、实现工作量评估

### 4.1 核心改动点

| 文件 | 改动类型 | 工作量 | 风险 |
|------|----------|--------|------|
| `App.vue` | 添加布局容器 | 1小时 | 低 |
| `HtmlSidebar.vue` | 无需改动 | 0小时 | 无 |
| `chat/index.vue` | 添加条件样式 | 2小时 | 中 |
| `global store` | 添加 sidebarVisible | 0.5小时 | 低 |
| CSS 全局样式 | 添加过渡动画 | 1小时 | 低 |
| 移动端适配 | 响应式断点 | 2小时 | 中 |

**总计：** 约 **6-8 小时**

### 4.2 详细步骤

#### 步骤 1：扩展 Store（15分钟）

```typescript
// store/modules/global/helper.ts
export interface GlobalState {
  // ... 现有属性
  sidebarVisible: boolean  // 新增
}
```

#### 步骤 2：修改聊天页面布局（2小时）

```vue
<!-- views/chat/index.vue -->
<template>
  <div
    class="chat-wrapper"
    :class="{ 'compressed': globalStore.sidebarVisible }"
  >
    <!-- 现有聊天内容 -->
  </div>
</template>

<style scoped>
.chat-wrapper {
  width: 100%;
  transition: width 0.3s cubic-bezier(0.4, 0, 0.2, 1);
}

.chat-wrapper.compressed {
  width: calc(100% - var(--sidebar-width, 50%));
  max-width: calc(100% - 400px); /* 最小聊天宽度 */
}
</style>
```

#### 步骤 3：响应式处理（2小时）

```css
/* 移动端保持全屏覆盖 */
@media (max-width: 768px) {
  .chat-wrapper.compressed {
    width: 100%;
  }
}
```

## 五、风险与注意事项

### 5.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 聊天容器定位错误 | 高 | 中 | 使用 CSS Grid 包裹 |
| 响应式布局冲突 | 中 | 中 | 严格测试断点 |
| 动画卡顿 | 低 | 低 | 使用 transform 而非 width |
| 第三方组件样式冲突 | 中 | 低 | 添加 CSS 隔离 |

### 5.2 用户体验风险

**问题：** 聊天界面变窄后，代码块可能显示不全

**解决方案：**
1. 设置最小宽度（如 400px）
2. 代码块添加水平滚动
3. 提供宽度调节滑块（30%-70%）

### 6.1 方案选择

**推荐：方案 B（动态宽度类）**

1. ✅ 改动最小，风险可控
2. ✅ 易于回滚
3. ✅ 不影响其他页面
4. ✅ 工作量适中（6-8小时）

### 6.2 实施优先级

## 七、代码示例

### 7.1 完整实现示例

```vue
<!-- views/chat/index.vue -->
<template>
  <div
    ref="chatWrapperRef"
    class="chat-wrapper"
    :class="{ 'sidebar-open': globalStore.showHtmlPreviewer }"
    :style="chatWrapperStyle"
  >
    <router-view />
  </div>
</template>

<script setup lang="ts">
import { computed } from 'vue'
import { useGlobalStoreWithOut } from '@/store'

const globalStore = useGlobalStoreWithOut()

// 响应式宽度
const chatWrapperStyle = computed(() => {
  if (!globalStore.showHtmlPreviewer) {
    return { width: '100%' }
  }

  const sidebarWidth = globalStore.sidebarConfig.width || 50
  return {
    width: `calc(100% - ${sidebarWidth}%)`,
    maxWidth: 'calc(100% - 350px)' // 最小侧边栏宽度
  }
})
</script>

<style scoped>
.chat-wrapper {
  transition: width 0.3s cubic-bezier(0.4, 0, 0.2, 1);
  min-width: 350px; /* 最小聊天宽度 */
}

/* 移动端不变 */
@media (max-width: 768px) {
  .chat-wrapper.sidebar-open {
    width: 100% !important;
  }
}
</style>
```

### 7.2 拖拽调节宽度

```vue
<!-- HtmlSidebar.vue 新增拖拽手柄 -->
<template>
  <div class="sidebar-container">
    <!-- 拖拽手柄 -->
    <div
      class="resize-handle"
      @mousedown="startResize"
    >
      <div class="handle-line"></div>
    </div>

    <!-- 侧边栏内容 -->
    <div class="sidebar-content">...</div>
  </div>
</template>

<script setup lang="ts">
const isResizing = ref(false)
const startX = ref(0)
const startWidth = ref(50)

const startResize = (e: MouseEvent) => {
  isResizing.value = true
  startX.value = e.clientX
  startWidth.value = globalStore.sidebarConfig.width

  document.addEventListener('mousemove', onResize)
  document.addEventListener('mouseup', stopResize)
}

const onResize = (e: MouseEvent) => {
  if (!isResizing.value) return

  const deltaX = startX.value - e.clientX
  const windowWidth = window.innerWidth
  const deltaPercent = (deltaX / windowWidth) * 100

  let newWidth = startWidth.value + deltaPercent
  newWidth = Math.max(30, Math.min(70, newWidth)) // 限制 30-70%

  globalStore.updateSidebarConfig({ width: Math.round(newWidth) })
}

const stopResize = () => {
  isResizing.value = false
  document.removeEventListener('mousemove', onResize)
  document.removeEventListener('mouseup', stopResize)
}
</script>

<style scoped>
.resize-handle {
  position: absolute;
  left: 0;
  top: 0;
  bottom: 0;
  width: 6px;
  cursor: col-resize;
  background: transparent;
  transition: background 0.2s;
  z-index: 10;
}

.resize-handle:hover {
  background: rgba(59, 130, 246, 0.3);
}

.handle-line {
  position: absolute;
  left: 2px;
  top: 50%;
  transform: translateY(-50%);
  width: 2px;
  height: 40px;
  background: #3b82f6;
  border-radius: 1px;
  opacity: 0;
  transition: opacity 0.2s;
}

.resize-handle:hover .handle-line {
  opacity: 1;
}
</style>
```

## 八、总结与建议

### 8.1 评估结论

| 评估维度 | 评分 | 说明 |
|----------|------|------|
| **必要性** | ⭐⭐⭐⭐☆ | 符合主流产品体验，显著提升可用性 |
| **技术难度** | ⭐⭐☆☆☆ | 中等难度，主要是布局调整 |
| **工作量** | ⭐⭐☆☆☆ | 6-8 小时即可完成 |
| **风险** | ⭐⭐☆☆☆ | 风险可控，可快速回滚 |
| **收益** | ⭐⭐⭐⭐⭐ | 用户体验大幅提升，更符合预期 |

### 8.2 最终建议

**✅ 建议实施**

**理由：**
1. 主流产品（Claude、Cursor、MarsCode）均采用此布局
2. 用户可以同时查看对话和预览，效率更高
3. 技术实现难度适中，风险可控
4. 工作量不大，6-8 小时可完成

**实施时机：**
- 建议 Phase 1.5 完成后立即实施
- 与现有拖拽调整宽度功能配合
- 作为 Phase 1.5 的补充优化

**可选的增强功能（优先级较低）：**
- 拖拽调节宽度（P1）
